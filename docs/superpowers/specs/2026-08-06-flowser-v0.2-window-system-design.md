# Flowser v0.2 Window System Design

## Goal

Upgrade Flowser from a fixed proof-of-concept overlay into a reliable responsive floating browser for Android phones and tablets, with resize, maximize/restore, minimize-to-bubble, a responsive browser toolbar, and persistent window state.

Samsung tablet is the primary physical test device, but all geometry and toolbar behavior must be responsive for phone and tablet screens.

## Scope

Flowser v0.2 includes:

- Dragging a floating browser window.
- Resizing from a bottom-right handle.
- Maximize and restore.
- Minimize to a draggable bubble.
- Restore from the bubble without reloading the active WebView.
- Bubble edge snap and close action.
- Responsive toolbar with back, forward, reload/stop, minimize, maximize/restore, overflow menu, and close.
- Overflow menu actions for address editing, navigation, home, copy URL, share URL, open externally, desktop-site toggle, zoom controls, minimize, maximize/restore, and close.
- Persistent position, size, last normal bounds, mode, URL, desktop mode, and zoom.
- Geometry clamping after resize, drag, maximize/restore, relaunch, and configuration changes.
- Foreground service notification with Restore, Minimize, and Close actions while the floating browser session exists.
- Unit tests for geometry, state transitions, and URL/menu behavior.
- GitHub Actions build and APK artifact.

## Non-goals

The following remain outside v0.2:

- Multiple tabs.
- Multiple floating windows.
- Bookmarks and full browsing history.
- File download manager.
- File upload picker.
- Camera, microphone, and location permission bridging.
- Ad blocking.
- Password manager or autofill integration.
- Release signing or Play Store publishing.
- Cross-device sync.

## User experience

### Launch

1. User opens Flowser.
2. User enters a URL and taps **Open floating browser**.
3. Flowser requests overlay permission if required.
4. The floating browser opens using the last saved normal bounds, clamped to the current usable display area.
5. If no saved bounds exist, Flowser opens at a responsive default size.

### Window states

The browser session has four explicit states:

```text
WINDOWED
MAXIMIZED
MINIMIZED
CLOSED
```

Valid transitions:

```text
WINDOWED -> MAXIMIZED
WINDOWED -> MINIMIZED
WINDOWED -> CLOSED
MAXIMIZED -> WINDOWED
MAXIMIZED -> MINIMIZED
MAXIMIZED -> CLOSED
MINIMIZED -> WINDOWED or MAXIMIZED, depending on the pre-minimize state
MINIMIZED -> CLOSED
```

`CLOSED` destroys the WebView and stops the service. `MINIMIZED` keeps the same WebView instance alive and hidden so page login, scroll position, form content, and navigation history survive restore.

### Dragging

- Dragging uses the toolbar background, excluding toolbar buttons.
- Window position is clamped inside the current usable screen bounds.
- The toolbar remains reachable after every drag.
- Position is saved after drag ends, not on every movement event.

### Resizing

- A visible 32 dp bottom-right resize handle is always available in `WINDOWED` state.
- Minimum window width: 280 dp.
- Minimum window height: 320 dp.
- Maximum bounds: current usable display width and height.
- Resize updates the WebView live.
- Resize cannot move the window outside the screen.
- Width and height are saved after resize ends.
- The handle is hidden in `MAXIMIZED` and `MINIMIZED` states.

### Maximize and restore

- Maximize fills the current usable display area without covering system insets.
- Before maximizing, Flowser saves `lastNormalBounds`.
- Restore returns to `lastNormalBounds`, clamped to the current display.
- Double-tapping the non-button toolbar area toggles maximize/restore.

### Minimize and bubble

- Minimize hides the browser window and displays a 56 dp bubble.
- Bubble shows a Flowser mark initially; favicon support is optional only if it can be added without new network or image dependencies.
- Bubble can be dragged.
- On release, bubble snaps to the nearest left or right edge.
- Tap restores the browser to the state it had before minimizing.
- Long press opens a compact menu with **Restore** and **Close**.
- Dragging the bubble into a visible bottom close target closes the browser session.
- Bubble position and side are persisted.

### Toolbar

Wide layout:

```text
[Back] [Forward] [Title/domain] [Reload/Stop] [Minimize] [Maximize/Restore] [Menu] [Close]
```

Compact layout:

```text
[Back] [Title/domain] [Reload/Stop] [Minimize] [Menu]
```

Compact mode activates when the window width is below 420 dp. Forward, maximize/restore, and close remain available in the overflow menu.

Toolbar behavior:

- Back and Forward enabled states follow WebView navigation state.
- Reload changes to Stop while a page is loading.
- Title area displays page title when available, otherwise host/domain.
- Tapping title area opens an address editor.
- Toolbar controls use minimum 48 dp touch targets.

### Overflow menu

The menu contains:

- Edit address.
- Back.
- Forward.
- Reload or Stop.
- Home.
- Minimize.
- Maximize or Restore.
- Open in default browser.
- Copy URL.
- Share URL.
- Desktop site toggle.
- Zoom in.
- Zoom out.
- Reset zoom.
- Close Flowser.

Unavailable actions are disabled rather than removed.

## Architecture

### FloatingBrowserService

Responsibilities:

- Own the browser session lifetime.
- Enter foreground mode and maintain notification actions.
- Receive commands through intents.
- Construct and connect controllers.
- Destroy all resources on close.

The service must no longer contain detailed drag, resize, bubble, toolbar, or WebView UI logic.

### FloatingWindowController

Responsibilities:

- Add and remove the browser overlay.
- Apply `WindowGeometry` to `WindowManager.LayoutParams`.
- Handle drag, resize, maximize, restore, and clamping.
- Notify state persistence only when gestures complete.
- Recalculate usable bounds from current display metrics and insets.

### BubbleController

Responsibilities:

- Add and remove the minimized bubble overlay.
- Drag and edge-snap the bubble.
- Display and manage the close target.
- Restore or close the browser session.

### BrowserSessionController

Responsibilities:

- Create and own one WebView.
- Load URL and expose current title, URL, loading state, navigation state, desktop mode, and zoom.
- Implement back, forward, reload, stop, home, desktop mode, and zoom actions.
- Retain the same WebView instance during minimize/restore.
- Destroy WebView exactly once on close.

### BrowserToolbarController

Responsibilities:

- Build the toolbar view.
- Render wide or compact controls based on current width.
- Forward actions to `BrowserSessionController` and `FloatingBrowserService`.
- Show address editor and overflow menu.

### WindowStateRepository

Responsibilities:

- Persist and restore `BrowserWindowState` through SharedPreferences.
- Reject corrupt or impossible stored values by applying defaults and clamping.
- Store state only at meaningful checkpoints.

## Data model

```kotlin
enum class WindowMode {
    WINDOWED,
    MAXIMIZED,
    MINIMIZED,
    CLOSED
}

data class WindowGeometry(
    val x: Int,
    val y: Int,
    val width: Int,
    val height: Int
)

data class BrowserWindowState(
    val mode: WindowMode,
    val geometry: WindowGeometry,
    val lastNormalGeometry: WindowGeometry,
    val preMinimizeMode: WindowMode,
    val bubbleX: Int,
    val bubbleY: Int,
    val currentUrl: String,
    val desktopMode: Boolean,
    val zoomPercent: Int
)
```

`preMinimizeMode` may only be `WINDOWED` or `MAXIMIZED`. Invalid persisted values fall back to `WINDOWED`.

## Geometry rules

All geometry calculations use pixels internally and dp only for constants.

`WindowGeometryEngine` is a pure Kotlin component with no Android View dependency. It provides:

```kotlin
fun defaultGeometry(bounds: RectSize, density: Float): WindowGeometry
fun clampWindow(geometry: WindowGeometry, bounds: RectSize, density: Float): WindowGeometry
fun resizeFromBottomRight(
    start: WindowGeometry,
    deltaX: Int,
    deltaY: Int,
    bounds: RectSize,
    density: Float
): WindowGeometry
fun maximizedGeometry(bounds: RectSize): WindowGeometry
fun snapBubble(
    x: Int,
    y: Int,
    bubbleSizePx: Int,
    bounds: RectSize
): Point
```

Rules:

- Minimum size is enforced before position clamping.
- Maximum size never exceeds usable bounds.
- `x` is within `0..bounds.width-width`.
- `y` is within `0..bounds.height-toolbarReachableHeight` during drag.
- Restored and persisted geometry is always clamped before use.
- Rotation does not discard normal bounds; it clamps them to the new display.

## Service lifecycle and notification

While a browser session is open or minimized:

- Flowser runs as a foreground service.
- A low-importance persistent notification is shown.
- Notification actions: Restore, Minimize, Close.
- Closing removes overlays, destroys WebView, stops foreground mode, and stops the service.
- Repeated launch commands update the existing session URL instead of creating a second service session.

## Error handling

- Overlay permission missing: stop safely and return user to the launcher status message.
- WindowManager add/update/remove failure: catch, clean up known views, and stop the service if the main browser window cannot be shown.
- Invalid saved state: use defaults.
- Invalid requested URL: reject before starting the service.
- WebView render process termination: show a lightweight error view with Reload and Close.
- External browser/share/copy action unavailable: keep Flowser running and show a short Toast.
- Configuration change: recompute bounds, clamp current geometry, and redraw the correct state.

## Testing

### Unit tests

Pure Kotlin tests must cover:

- Default geometry on phone and tablet bounds.
- Minimum and maximum resize constraints.
- Resize near every screen edge.
- Drag clamping.
- Maximize and restore geometry.
- Rotation clamping.
- Bubble left/right snapping.
- Window state transition validity.
- Invalid persisted mode fallback.
- Desktop mode and zoom bounds.

Zoom range:

- Minimum: 50 percent.
- Maximum: 200 percent.
- Step: 10 percent.
- Reset: 100 percent.

### Build verification

GitHub Actions must run:

```text
gradle --no-daemon testDebugUnitTest
gradle --no-daemon assembleDebug
```

The debug APK must be uploaded as `flowser-debug-apk`.

### Physical-device acceptance tests

Primary:

- Samsung tablet shown in the user-provided screenshot.

Additional coverage:

- Small phone viewport.
- Android 8 or 9 emulator/device.
- Android 12 emulator/device.
- Android 15 emulator/device.

Acceptance checklist:

- Resize works smoothly and never loses the toolbar.
- Maximize and restore preserve normal bounds.
- Minimize and restore preserve WebView session and scroll position.
- Bubble drags, snaps, restores, and closes.
- App behind Flowser remains touchable outside overlay bounds.
- Compact toolbar appears below 420 dp width.
- Position and size survive service restart.
- Portrait/landscape changes do not strand the window off-screen.
- Notification actions work.
- Build, unit tests, and artifact upload pass.

## Migration from v0.1

- Keep package name `com.flowser.app`.
- Keep current URL normalization behavior.
- Keep Android minimum SDK 26.
- Replace the monolithic `FloatingBrowserService` implementation with controller-based composition.
- Preserve existing SharedPreferences key for last URL or migrate it once into `BrowserWindowState.currentUrl`.
- Existing v0.1 users should install v0.2 over the current debug build without clearing app data.

## Definition of done

Flowser v0.2 is done when the acceptance checklist passes, the code is merged to `main`, GitHub Actions is green on `main`, and a downloadable debug APK artifact is available. Runtime behavior must be confirmed on the Samsung tablet before declaring device acceptance complete.
